# Baseline Hybrid와 PageIndex의 검색 결과 비교

**정답 문서가 표본에 있는 24문항에서 하이브리드는 22문항, PageIndex는 2문항의 정답을 상위 10개 문서 안에 반환했다.** 차이는 주로 문서를 고르는 순서에서 발생했다. 하이브리드는 전체 문서의 본문 청크를 검색한다. 이번 PageIndex 구현은 제목과 짧은 발췌로 문서를 먼저 고르는데, 이 단계에서 이미 24문항 중 21문항의 정답 문서가 빠졌다. [평가 요약과 검산 결과](pageindex-sample180-summary.json)

## 두 방식이 검색하는 순서

2026년 11월 22일 `pageindex` 브랜치의 `e907ed4`에서 EnterpriseRAG-Bench 공식 500문항을 평가했다. 두 방식에 같은 9개 소스의 180문서, 1,200자 청크 1,248개(겹침 160자), 최대 50개 반환 청크를 적용했다. PageIndex 0.2.10의 Markdown 파서가 문서별 목차를 만들고, 프로젝트에서 구현한 검색기가 여러 문서 중 열어볼 목차를 선택한다. [실험 설정과 재현 명령](pageindex-verification.md)

| 단계 | Baseline Hybrid (C2) | PageIndex (PI) |
| --- | --- | --- |
| 처음 보는 정보 | 1,248개 청크의 제목·본문 키워드와 본문 임베딩 | 문서 제목 최대 110자, 소스 종류, 본문 앞부분에서 만든 발췌 최대 64자 |
| 후보 선택 | PostgreSQL 키워드 검색과 Model2Vec 벡터 검색에서 각각 상위 50청크를 뽑는다. 각 청크가 등장한 목록마다 `1 / (60 + 순위)`를 더해 최종 순위를 정한다. | 로컬 Qwen2.5-1.5B-Instruct가 문서를 최대 20개씩 비교한다. 묶음별 후보를 모아 다시 순위를 정하고 최대 20문서를 남긴다. |
| 최종 반환 | 결합 점수가 높은 청크를 반환한다. 평가기는 청크가 처음 등장한 순서대로 고유 문서 순위를 매긴다. | 선택한 문서의 목차를 탐색하고 근거가 되는 원문 구간을 고른다. 선택된 구간을 담은 청크만 반환하므로 앞 단계에서 빠진 문서는 최종 결과에 들어올 수 없다. |

하이브리드에서는 긴 회의록 뒤쪽의 한 문장도 첫 검색에서 후보가 될 수 있다. PageIndex에서는 그 회의록이 문서 선택을 통과해야 같은 문장을 읽을 기회가 생긴다. ## 측정 결과

| 지표 | 하이브리드 | PageIndex |
| --- | ---: | ---: |
| 문서 Recall@1 | 3.40% | 0.43% |
| 문서 Recall@10 | 4.18% | 0.43% |
| 상위 10개 문서에서 정답을 하나 이상 찾은 문항 | 22/24 | 2/24 |
| 질문당 최종 반환한 고유 문서 수(평균) | 23.48개 | 0.80개 |
| 검색 지연 중앙값 | 19.41ms | 21.82초 |
| 검색 지연 95백분위 | 41.85ms | 57.45초 |

Recall은 정답 문서 ID가 있는 470문항에서 질문별로 찾은 정답 문서의 비율을 평균한 값이다. 이 중 446문항은 표본에 정답이 하나도 없었다. 22/24와 2/24는 표본에서 답을 찾을 기회가 있었던 24문항의 적중 건수다. 반환 문서 수와 검색 지연은 500문항 전체에서 측정했다. [지표별 집계](pageindex-sample180-summary.json)

**후보 단계에서의 손실.** PageIndex가 선택한 후보는 질문당 평균 2.74문서였고, 정답을 후보에 포함한 경우는 3/24였다. 이 후보를 그대로 사용하면 목차와 근거를 완벽하게 선택해도 최대 3문항이 적중한다. 하이브리드가 적중한 22문항 중 19문항은 PageIndex 후보에 정답이 없었다. 같은 Gmail 문서(`dsid_802b8c0343c746469052e7f2f58404c8`)가 244개 질문에서 후보로 반복 선택되기도 했다. 이 수치는 측정 당시의 모델과 후보 선택 설정에 해당한다. 문항별 후보는 재현 명령으로 생성되는 `experiments/results/pageindex-sample180.json`의 PI 검색 기록에 담겨 있다. [측정 조건과 재현 명령](pageindex-verification.md#재현과-자동-테스트)

**지연이 발생하는 과정.** 하이브리드는 질문 임베딩을 한 번 계산하고 두 DB 검색 결과의 순위를 결합한다. PageIndex는 500문항에 로컬 모델을 6,119회, 질문당 평균 12.24회 호출했다. 문서 선택에 5,002회, 목차 선택에 589회, 근거 선택에 528회를 사용했다. 단계별 수치는 호출 횟수이며 표의 지연은 한 질문의 검색 전체에 걸린 시간이다. 공식 측정에 포함된 시간 초과 4건은 모두 표본에 정답이 없는 질문에서 발생했다. [모델 호출과 종료 사유](pageindex-sample180-summary.json)

## 실제 사례 · GCP Marketplace 구독 지연

공식 질문 `qst_0004`는 새 구독의 권한 반영이 늦을 때 온보딩 화면에서 무엇을 안내해야 하는지 묻는다. 정답은 Fireflies 회의록 **GCP Marketplace onboarding + billing review (Redwood Inference)**에 있다. 문서 ID는 `dsid_6c4c1c875e704f09b4d791d64d7bc7e5`다.

| 확인 지점 | 하이브리드 | PageIndex |
| --- | --- | --- |
| 회의록을 찾았는가 | 회의록의 첫 청크가 키워드 1위, 벡터 4위로 결합 순위 1위에 올랐다. 회의록도 문서 1위였다. | 최종 문서 후보는 Slack의 `eng-platform`과 `eng-releases`였다. 제목에 GCP Marketplace가 명시된 정답 회의록은 이 단계에서 빠졌다. |
| 안내 문구를 찾았는가 | “구독을 동기화 중이니 몇 분 뒤 다시 시도하라”는 원문 구간 `[6332, 6393)`을 담은 청크는 11위였다. | 두 Slack 후보의 목차를 탐색한 뒤 반환한 근거는 0개였다. |

이 질문에서 하이브리드의 **문서 1위**는 올바른 회의록을 찾았다는 뜻이다. 정확한 안내 문구를 읽으려면 반환된 청크를 **11위까지** 확인해야 했다. PageIndex에서는 회의록을 열기 전에 검색 경로가 갈렸다. [GCP 사례의 문서 순위와 원문 위치 검산](pageindex-sample180-summary.json)
